# خطة بناء المحاسب الذهبي ودمج المكونات

## القرار التقني
- التطبيق النهائي: Android أصلي، Kotlin، Jetpack Compose وMaterial 3، دعم RTL عربي كامل.
- قاعدة البيانات المحلية الوحيدة: Room/SQLite، مع العمل دون اتصال.
- فصل المحرك المحاسبي عن واجهات العرض: Core / Data / App.
- استخدام Long بوحدة نقدية صغرى ثابتة أو BigDecimal للحسابات؛ يمنع Float/Double للأموال.
- لا بيانات تجريبية في تجربة المستخدم النهائية. عند أول تشغيل تظهر إعدادات المنشأة فقط ثم دليل حسابات نظامي ينشأ مرة واحدة.
- لا تُرحّل أي عملية غير متوازنة، وتُحفظ الفاتورة والمخزون والقيد داخل معاملة واحدة.
- لا حذف مباشر للعمليات المرحلة؛ الإلغاء والتصحيح بقيد عكسي مع سجل تدقيق.

## سياسة الاستفادة من مشاريع GitHub
المشاريع المرشحة للفحص: Hisab App، Accounting System، AlKhal، Hithvi Ledger، Vynex، BMS، وMini POS Inventory Flutter.
هذه أسماء مرشحة وليست موافقة مسبقة على نسخ الكود أو دليلاً على اكتمال ميزاتها.

قبل اقتباس أي كود:
1. تأكيد أن المستودع والرابط والمحتوى متاحون فعلاً.
2. قراءة LICENSE والتحقق من شروط إعادة الاستخدام والإسناد والتوافق.
3. فحص تاريخ آخر تحديث، بنية التطبيق، الاختبارات، ومخرجات البناء إن توفرت.
4. تدوين الملفات/الأفكار المقتبسة ومصدرها وترخيصها.
5. إذا لم توجد رخصة واضحة، لا ننسخ الكود؛ نعيد تنفيذ السلوك المطلوب بصورة مستقلة.
6. لا ندمج أطر عمل متعارضة داخل التطبيق. نعيد استخدام الأفكار والمكونات القابلة للفصل فقط.

## ترتيب التنفيذ
1. تدقيق المستودع الحالي والكود الحالي والبناء السحابي.
2. تثبيت بنية Compose والتنقل العربي وRTL والهوية الذهبية/الكحلية.
3. تدقيق قاعدة البيانات والمخطط والترحيلات.
4. اختبار المحرك المحاسبي: القيود، الفواتير، الدفعات، المرتجعات، تكلفة البضاعة والمخزون.
5. استكمال الحسابات والعملاء والموردين والصناديق والبنوك.
6. استكمال المستودعات والجرد والتحويل والتسوية والباركود.
7. التقارير المالية والتشغيلية والفلاتر الزمنية.
8. النسخ الاحتياطي والاستعادة، الصلاحيات، سجل التدقيق، PDF والطباعة.
9. اختبارات آلية ثم بناء APK سحابي والتحقق من الـ artifact.

## معايير قبول كل مرحلة
- نجاح Gradle وGitHub Actions.
- اختبارات الوحدة للحسابات والقيود والتقارير.
- عدم وجود بيانات وهمية أو WebView أو HTML/JavaScript.
- العربية وRTL في كل الشاشات.
- اختبار الاستعادة من نسخة احتياطية، وعدم فقدان الاتساق بين الفواتير والقيود والمخزون.
- عدم الادعاء بنجاح APK قبل التحقق من نتيجة Actions ووجود ملف APK في Artifacts.
