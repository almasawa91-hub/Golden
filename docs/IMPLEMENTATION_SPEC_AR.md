# Golden — مواصفات التنفيذ النهائية

## 0. الهدف
تحويل المستودع إلى تطبيق Android Native محاسبي ومخازن جاهز للاستخدام والنشر، مع الحفاظ على تجربة الاستخدام البسيطة والمباشرة المستوحاة من محاسب سوفت، دون نسخ الهوية أو الأصول، ودون WebView أو HTML/JavaScript.

المبدأ: **نحافظ على شكل وطريقة التنقل الحالية التي يحبها المستخدم، ونبني تحتها محرك بيانات ومحاسبة حقيقي بالكامل.**

## 1. قواعد غير قابلة للتفاوض
- Kotlin + Jetpack Compose + Material 3.
- Room/SQLite كمصدر البيانات المحلي الوحيد.
- MVVM + Repository + Use Cases + Coroutines + Flow/StateFlow.
- RTL عربي كامل.
- لا WebView.
- لا HTML/JavaScript محلي.
- لا بيانات تجريبية أو Fake/Demo data.
- أول تشغيل: شركة/إعدادات أساسية فقط، وباقي البيانات فارغة.
- لا أرصدة مخزنة كمصدر للحقيقة؛ الأرصدة والتقارير تحسب من الحركات والقيود.
- ممنوع Float/Double للأموال؛ استخدم Long بوحدة ثابتة أو BigDecimal داخل المحرك.
- كل عملية مالية يجب أن تنتج قيداً متوازناً: مجموع المدين = مجموع الدائن، وإلا تُرفض العملية بالكامل.
- لا حذف مباشر للعمليات المرحّلة؛ الإلغاء/التصحيح يتم بعكس العملية مع Audit Log.
- لا IDs محاسبية hard-coded داخل الواجهات؛ الحسابات النظامية تُنشأ وتُحل من Registry/Settings.
- جميع عمليات الفاتورة + المخزون + القيد تتم داخل Transaction واحدة.
- يجب أن يعمل التطبيق Offline بالكامل في الوظائف الأساسية.

## 14. النسخ والاستعادة
Backup:
- نسخة SQLite/بيانات منطقية آمنة.
- تتضمن schema version + app version + checksum + company identifier.
- تصدير إلى ملف يختاره المستخدم.
- لا تكتب فوق النسخة الأصلية تلقائياً.

Restore:
- التحقق من نوع الملف.
- التحقق من schema/version/checksum.
- عرض ملخص قبل الاستعادة.
- إنشاء backup للحالة الحالية قبل الاستبدال.
- استعادة Transactionally.
- إعادة فتح DB بعد نجاح الاستعادة.
- رفض ملف تالف أو غير متوافق.

## 21. معايير قبول المنتج النهائي
لا تعتبر المرحلة مكتملة إلا إذا:
1. لا يوجد WebView في التطبيق.
2. لا توجد بيانات Fake/Demo.
3. كل شاشة تعرض بيانات Room الحقيقية.
4. العمليات المالية تغير المخزون والقيود بصورة متسقة.
5. مجموع المدين = مجموع الدائن دائماً.
6. يمكن إنشاء شركة فارغة ثم تشغيل دورة بيع/شراء كاملة.
7. يمكن استخراج كشف حساب وتقارير صحيحة من نفس البيانات.
8. backup/restore يعملان.
9. التطبيق يدعم RTL بالكامل.
10. CI ينفذ test + lint + assembleDebug بنجاح.
11. Release APK وAAB يبنيان بنجاح.
12. لا توجد TODOs حرجة أو شاشات وهمية في المسار الأساسي.

## 23. تعريف الإنجاز
لا تستخدم عبارة "اكتمل التطبيق" لمجرد أن Gradle نجح.
الإنجاز الحقيقي = **Build ناجح + اختبارات ناجحة + دورة محاسبية كاملة تعمل على بيانات حقيقية + Backup/Restore + واجهة مكتملة + Release APK/AAB**.
