# قرار مرجع التصميم — المحاسب الذهبي

## القرار
يُبنى تصميم المحاسب الذهبي بالاستناد إلى أنماط الاستخدام الظاهرة في المستودعات المرجعية، مع واجهة أصلية موحدة بـ Kotlin + Jetpack Compose + Material 3. لا تُنسخ واجهات Flutter حرفياً ولا تُخلط أنظمة تصميم متعارضة.

## ترتيب المراجع حسب الاستخدام
1. **Hisab App** — https://github.com/usingn50/hisab-app
   - المرجع الأول لتبسيط تجربة صاحب المحل، وضوح العربية، العمليات السريعة، الديون ولوحة متابعة العمل اليومي.
   - الرخصة الظاهرة في بيانات المستودع: MIT؛ يجب مراجعة ملف LICENSE الفعلي قبل نسخ أي كود أو أصل.

2. **Accounting System** — https://github.com/corectrlplus/accounting_system
   - مرجع وظيفي لتنظيم شاشات الحسابات والتقارير المالية ودليل الحسابات.
   - لا يُنسخ منه كود قبل التأكد من ملف الترخيص الفعلي؛ وجود مستودع عام لا يعني تلقائياً السماح بإعادة الاستخدام.

3. **Vynex Mobile** — https://github.com/victor964/Vynex_mobile
   - مرجع لشاشات المنتجات والمخزون والعملاء والديون والتقارير وPDF والنسخ الاحتياطي.
   - يجب التحقق من ملف LICENSE قبل اقتباس أي كود أو أصول.

4. **BMS** — https://github.com/getbms/bms
   - مرجع إضافي لتجربة نقطة البيع والعمليات التشغيلية. بيانات المستودع تعرض Apache-2.0، ويجب الالتزام بشروطها إذا اقتُبس كود.

5. **Mini POS Inventory Flutter** — https://github.com/AmrNabil12/Mini-POS-Inventory-Flutter
   - مرجع لسير البيع السريع والمرتجعات وحركة المخزون والإيصالات.
   - بيانات المستودع تعرض MIT؛ راجع ملف LICENSE قبل إعادة استخدام الكود.

6. **AlKhal** و **Hithvi Ledger**
   - مرجعان احتياطيان لأفكار تدفق العمل، بعد فحص الشاشات والترخيص والبناء.

## قواعد الهوية البصرية الموحدة
- اللغة الأساسية: العربية، واتجاه RTL حقيقي لكل الشاشة والمكونات.
- لوحة ألوان الهوية: ذهبي #D4AF37 وذهبي داكن #A67C00، كحلي #0F172A، أزرق #1E40AF، خلفية #F8FAFC، سطح أبيض #FFFFFF، نجاح #059669، خطر #DC2626، تحذير #D97706.
- اللون الذهبي للتأكيد والعناصر الرئيسية فقط، وليس خلفية كل الشاشة.
- بطاقات مؤشرات موجزة، تسلسل بصري واضح، أزرار إجراءات سريعة، وجداول/قوائم سهلة القراءة على الهاتف.
- توحيد ارتفاعات الحقول والأزرار، حالات التحميل/الفراغ/الخطأ، رسائل التأكيد، والتنسيق الرقمي والعملة.
- لا تظهر بيانات وهمية أو رسوم بيانية مزيفة؛ الحالة الفارغة توضح للمستخدم كيف يضيف بياناته.
- لا WebView أو HTML/JavaScript. الواجهات Native Compose.
- الحفاظ على الوظائف وسهولة التنقل؛ لا نقل حرفي للعلامة التجارية أو الأصول أو النصوص الخاصة بالمشاريع المرجعية.

## خريطة الشاشات التي يجب أن تتبع النظام الموحد
- الإعداد الأول للمنشأة.
- الرئيسية والمؤشرات.
- المبيعات: إنشاء فاتورة، سجل الفواتير، المرتجعات.
- المشتريات: إنشاء فاتورة، سجل الفواتير، المرتجعات.
- الحسابات: شاشة موحدة بفئات قابلة للتمرير، كشف حساب، إضافة/تعديل حساب.
- دليل الحسابات الهرمي.
- سند قبض وسند صرف والقيود اليومية.
- الأصناف والباركود والوحدات.
- المخازن وحركة الصنف والجرد والتحويل والتسوية.
- التقارير المالية والتشغيلية مع فلاتر تاريخية.
- الإعدادات والنسخ الاحتياطي والاستعادة والمستخدمون والصلاحيات والطباعة.

## بوابة قبول التصميم
قبل اعتبار أي شاشة مكتملة:
1. RTL صحيح في النصوص والأيقونات والحقول والتنقل.
2. تتبع ألوان ومسافات ومكونات موحدة.
3. تتصل بمصدر البيانات الحقيقي وتعرض حالة الفراغ بشكل صحيح.
4. تعمل أزرارها والتنقل والرجوع والحفظ والتحقق من الأخطاء.
5. لا تتضمن أرقاماً أو سجلات تجريبية.
6. تمر اختبارات البناء وLint، وتضاف اختبارات منطق الشاشة حيث يلزم.

## ملاحظة مهمة
اختيار المرجع لا يعني أن كل ميزة في المستودع منفذة أو مختبرة. يجب التحقق من الكود والاختبارات وملف LICENSE قبل اقتباس أي تنفيذ. عند عدم وضوح الترخيص، نستخدم المرجع لفهم السلوك فقط ونكتب تنفيذاً مستقلاً.
